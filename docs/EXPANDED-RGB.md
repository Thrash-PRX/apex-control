# Expanded RGB catalogue

APEX native mode IDs are from captured 0x18/0x98 name readback, not copied from WK68 or Wooting. Hardware Apply now accepts only integer IDs0–11 and still requires the selected record to be present in the current device table. It backs up all RGB records, preserves raw unknown fields, writes the selected settings, selects the mode, checks acknowledgements and rereads settings. Generic writes remain locked.

Mappings: Off0, Static1, stored Layer palette2, Breath3, Star4, Flow L→R5/R→L6/Up→Down7/Down→Up8, Dot(Press)9, Cross(Press)10, Ripple(Press)11. Wave direction chooses the corresponding captured Flow ID. Layer mode uses the existing device palette; the editor does not yet write individual key colors. Native firmware may ignore color/speed fields for particular modes. Only earlier Static RGB Apply has user-confirmed end-to-end success; additional native modes need physical confirmation.

WK68 reference labels and hashes remain in wk68-rgb-reference.json. Authored preview renderer reused from the user's earlier local APEX Studio project; it is not vendor source or firmware code. Added flash, rain, wheel, twinkle, shadow, snake, neon, sine, scanner, windmill, waterfall, blossom and storm previews, plus original fireworks and heatmap. Existing static/breathing/rainbow/reactive/ripple/custom/off remain. Browser previews are illustrative, including repeating selected-key origins, not reproductions of proprietary algorithms. Stored Layer preview is blank because the physical palette is not loaded into the preview.

Wootility's effect-layer concept is described in the official changelog: https://wooting.com.cn/wootility/changelogs/4.6.6 ; current Wootility ripple support is documented at https://wooting.io/wootility/changelogs/5.0.0 . Added an original local max-channel compositing overlay (Reactive/Ripple). No Wooting commands or vendor algorithms are copied. Overlay is preview-only and disables hardware Apply. No analog pressure or system-wide key capture is claimed.

No verified APEX per-key streaming/memory-persistence path exists yet. Do not turn static configuration packets into a high-rate animation stream without establishing buffer/persistence behavior and physical key-index mapping. Capture investigation of stock per-key painting is pending; a single key mapping cannot prove the whole board or safe streaming. Software previews cannot add firmware effects to APEX.

Per-key investigation: user confirmed only W turned red, then only W turned blue. First capture was stopped before isolated red and contains grouped writes only; it is not a W mapping fixture. Second capture includes APEX descriptor314B:1026 and isolated [FA,10,1,1,0,5,80,0,0,255,34] (decimal), padded64; user confirmed only W blue. This establishes W→34 and blueRGB for that path. Leading80 remains raw. Grouped traffic also selects mode255 via19 and uses two10 frames, excluding indices14/15. Custom255 is distinct from the name-table Layer2; do not conflate them. Persistence behavior and full-board streaming remain unknown; no host animation stream or per-key write API has been enabled. Both captures stopped; raw PCAPs private.
